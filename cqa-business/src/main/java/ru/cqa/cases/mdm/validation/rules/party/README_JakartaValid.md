# Валидация формы DTO (Jakarta Bean Validation)

Первый слой проверки запроса `saveAndMerge`: **форма** — есть ли нужные объекты, списки
и ключевые поля. Проверки объявлены аннотациями прямо на DTO модуля `cqa-model`,
выполняет их Hibernate Validator. Смысл значений реквизитов проверяет второй слой —
[правила бизнес-логики](README.md).

| Что проверяем | Где | Чем |
|---|---|---|
| структура запроса: party, field, attribute, обязательные свойства | DTO в `cqa-model` | аннотации `jakarta.validation` |
| значения реквизитов: `identificationLevel`, даты, ФИО, СНИЛС... | `rules/party` | классы `Rule<PartyDTO>` |

Реквизиты приходят парами `{"name": ..., "value": ...}`, поэтому аннотацией нельзя сказать
«реквизит `identificationLevel` обязателен» — у DTO нет такого поля. Это задача правил.

---

## Как это работает

1. Контроллер принимает тело сырыми байтами и разбирает его в `SaveAndMergeDTO`.
   `@Valid` на параметре контроллера **намеренно нет**.
2. Контроллер выбирает валидатор по `party[0].type`: `PHYSICAL` или `LEGAL`. Если `party`
   пустой или тип другой, ответ сразу `400` с одной ошибкой
   `party[0].type: ожидается одно из [PHYSICAL, LEGAL]` — форма тогда не проверяется.
3. Адаптер [BeanFormValidator](../../../../../../../../../../../cqa-validation/src/main/java/ru/cqa/validation/BeanFormValidator.java) (его через интерфейс `FormValidator` вызывает
   [SaveAndMergeValidator](../../../../../validators/mdm/SaveAndMergeValidator.java)) вызывает
   `validator.validate(request)` — проверяется всё дерево объектов разом, без остановки
   на первой ошибке.
4. Каждое нарушение превращается в строку `путь: сообщение`; строки сортируются по алфавиту.
5. Если `party[0]` есть, следом запускаются правила бизнес-логики своего типа участника —
   даже когда форма уже с ошибками.
6. Все ошибки уходят клиенту одним списком, ответ `400`.

До проверки формы дело не доходит, если тело не разобралось в DTO: это не JSON или
тип не тот (`"party": "abc"`). Тогда ответ `400` в формате ProblemDetail от
`ApiExceptionHandler`, а не список ошибок. Лишние поля в JSON игнорируются.

### Путь в сообщении

| Нарушение | Путь |
|---|---|
| свойство объекта | `updateType: ...` |
| свойство элемента списка | `party[0].field[2].name: ...` |
| сам элемент списка (`List<@NotNull X>`) | `party[0].field[1]: ...` |

Hibernate добавляет к пути элемента служебное `.<list element>` — `BeanFormValidator`
его вырезает.

## Аннотации по DTO

### SaveAndMergeDTO — корень запроса
[SaveAndMergeDTO](../../../../../../../../../../../cqa-model/src/main/java/ru/cqa/model/mdm/SaveAndMergeDTO.java)

| Свойство | Аннотации | Требование |
|---|---|---|
| `party` | `@NotEmpty`, `@Size(max = 1)`, элементы `@NotNull @Valid` | ровно один участник, не null; проверяется вглубь |
| `include` | `@Valid` | необязателен; своих ограничений у `IncludeDTO` нет |
| `updateType` | `@NotBlank` | обязателен, непустой; значение не проверяется |

| Вход | Итог |
|---|---|
| `"party": [ {...} ]` | ✅ |
| `party` нет / `null` / `[]` | ❌ `party: Требуется 1 объект` |
| два участника | ❌ `party: Требуется 1 объект` |
| `"party": [null]` | ❌ `party[0]: ...` — сообщение Hibernate по умолчанию |
| `updateType` нет / `""` / `"  "` | ❌ `updateType: Не должно быть пустым` |
| `updateType: "ANY"` | ✅ |

### PartyDTO — участник
[PartyDTO](../../../../../../../../../../../cqa-model/src/main/java/ru/cqa/model/mdm/PartyDTO.java)

| Свойство | Аннотации | Требование |
|---|---|---|
| `type` | `@NotBlank` | обязателен; значение (`PHYSICAL` / `LEGAL`) проверяется ещё до формы — по нему выбирается валидатор |
| `sourceSystem` | `@NotBlank` | обязателен |
| `rawId` | `@NotBlank` | обязателен |
| `field` | `@NotEmpty`, элементы `@NotNull @Valid` | хотя бы один реквизит, без null |
| `attribute` | элементы `@Valid` | необязателен; null-элементы форма пропускает — их ловят правила |

| Вход | Итог |
|---|---|
| все свойства заполнены, `field` из одного реквизита | ✅ — форма пройдена, остальное решают правила |
| `type` / `sourceSystem` / `rawId` пустой | ❌ `party[0].type: Не должно быть пустым` и т.п. |
| `field` нет / `[]` | ❌ `party[0].field: Не должна быть коллекция пустой` |
| `"field": [null]` | ❌ `party[0].field[0]: ...` — сообщение по умолчанию |
| `attribute` нет / `[]` | ✅ |
| `"attribute": [null]` | ✅ на этом слое; ❌ в правиле 18 |

### FieldDTO — реквизит
[FieldDTO](../../../../../../../../../../../cqa-model/src/main/java/ru/cqa/model/mdm/FieldDTO.java)

| Свойство | Аннотации | Требование |
|---|---|---|
| `name` | `@NotBlank` | имя реквизита обязательно |
| `value` | — | любое, в том числе `null`: пустое значение — забота правил |

| Вход | Итог |
|---|---|
| `{"name": "vip", "value": "TRUE"}` | ✅ |
| `{"name": "vip", "value": null}` / без `value` | ✅ |
| `{"name": "", "value": "TRUE"}` / без `name` | ❌ `party[0].field[0].name: Не должно быть пустым` |
| два реквизита с одним `name` | ✅ — форма не видит; в правилах останется последний |

### AttributeDTO — атрибут участника
[AttributeDTO](../../../../../../../../../../../cqa-model/src/main/java/ru/cqa/model/mdm/AttributeDTO.java)

| Свойство | Аннотации | Требование |
|---|---|---|
| `type` | `@NotBlank` | тип атрибута обязателен; допустимые значения — правило 18 |
| `rawId` | `@NotBlank` | обязателен (в Swagger не помечен обязательным) |
| `field` | элементы `@NotNull @Valid` | список необязателен, но без null |

| Вход | Итог |
|---|---|
| `type`, `rawId` заполнены, `field` нет | ✅ на этом слое; ❌ в правилах 4 и 6 |
| `type` пустой | ❌ `party[0].attribute[0].type: не должно быть пустым` (+ правило 18) |
| `rawId` пустой | ❌ `party[0].attribute[0].rawId: не должно быть пустым` |
| `"field": [null]` | ❌ `party[0].attribute[0].field[0]: ...` |

### IncludeDTO — состав ответа
[IncludeDTO](../../../../../../../../../../../cqa-model/src/main/java/ru/cqa/model/mdm/IncludeDTO.java)

Ограничений нет: `partyInfo` — любой список строк или его отсутствие.

## Паттерн: как добавить проверку формы

```java
public record PartyDTO(
        @NotBlank(message = "Не должно быть пустым")   // своё сообщение — всегда
        String type,

        @NotEmpty(message = "...")                       // сам список
        List<@NotNull @Valid FieldDTO> field,            // элементы: не null + проверить вглубь
        ...
```

1. **Аннотация на компоненте record** — Hibernate видит её на поле record'а.
2. **`message` указывать всегда.** Без него текст берётся из Hibernate и зависит
   от локали JVM (`must not be null` / `не должно равняться null`).
3. **Вложенный объект проверяется только с `@Valid`.** Без него аннотации внутри
   вложенного DTO молча игнорируются.
4. **Ограничения на элементы списка** пишутся в параметре типа: `List<@NotNull @Valid X>`.
   `@NotEmpty` на самом списке не запрещает null внутри.
5. **Аннотация — для формы, правило — для смысла.** Если проверка зависит от `name`
   реквизита, от других полей или от справочника — это правило в `rules/party`.

| Аннотация | Пропускает | Отклоняет |
|---|---|---|
| `@NotNull` | `""`, `[]` | `null` |
| `@NotEmpty` | `"  "` | `null`, `""`, `[]` |
| `@NotBlank` (только строки) | — | `null`, `""`, `"  "` |
| `@Size(max = 1)` | `null`, `[]`, один элемент | два и больше |

---

## Известные шероховатости

- Регистр сообщений разный: `Не должно быть пустым` в `PartyDTO`/`FieldDTO`,
  `не должно быть пустым` в `AttributeDTO`.
- `@NotNull` на элементах списков без своего `message` — текст по умолчанию.
- Пустой `attribute.type` даёт две ошибки: аннотация и правило 18.
