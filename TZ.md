## 0. Термины и сокращения

| Термин | Определение                                                                                         |
|---|-----------------------------------------------------------------------------------------------------|
| ТЕСТИРОВЩИК | Разрабатываемый сервис «Единый тестировщик» или CommonQA или CQA                                    |
| УЧАСТНИК | Система, взаимодействующая с MDM (WAY4, Siebel и др.)                                               |
| MDM | Master Data Management — управление основными (эталонными) данными; решение, в котором ведутся золотые карточки |
| Золотая карточка | Эталонная запись о субъекте в MDM                                                                   |
| Сценарий | Описание проверки: действия, ожидаемый результат, очистка данных                                    |
| Негативный сценарий | Сценарий, в котором ожидаемый результат — корректная ошибка MDM                                     |
| Прогон | Выполнение набора сценариев с формированием отчёта                                                  |
| Общий сценарий | Сценарий, входящий в прогон всех УЧАСТНИКОВ                                                         |
| Частный сценарий | Сценарий конкретного УЧАСТНИКА                                                                      |
| Kafka | Брокер сообщений контура                                                                            |
| e2e | End-to-end — сквозное тестирование                                                                  |

## 1. Цель и контекст
## Что делаем
- «Единый тестировщик» — (далее ТЕСТИРОВЩИК) сервис для проверки работы систем-участников (далее УЧАСТНИКи)
  с MDM-решением.
- ТЕСТИРОВЩИК не содержит логики предметной области: вся логика работы
  с карточками описывается в сценариях.
- Каждый сценарий описан человеко-читабельно в ветке в Confluence.
- ТЕСТИРОВЩИК исполняет сценарии, сравнивает фактический результат с ожидаемым,
  описанным в сценарии, и формирует отчёт.
- Каждый УЧАСТНИК подключается к ТЕСТИРОВЩИКу и выполняет прогон —
  набор сценариев: общих для всех УЧАСТНИКов и частных для конкретного
  УЧАСТНИКа. Набор сценариев может дополняться.
- Проверяются отправленные и полученные данные, включая сообщения в Kafka.
- Прогон успешен, только если успешны все его сценарии, включая
  негативные.
- После каждого сценария тестовые данные очищаются.
- В первой версии прогоны запускаются вручную, автоматический запуск —
  в следующих версиях.



## 2. Границы (Scope)
### Входит в ТЕКУЩУЮ версию
- Веб-сервер который принимает и отправляет запросы (REST)
- Чтение сценариев
- Исполнение сценариев и сравнение фактического результата с ожидаемым
- Чтение сообщений из Kafka
- Удаление данных после тестирования
- Хранение прогонов, запросов, ответов и событий (PostgreSQL)
- Запуск сценария по HTTP-запросу к эндпоинту

### НЕ входит (Non-goals) (для анализа в следующих версиях)
- Веб-интерфейс
- Логика предметной области в коде ТЕСТИРОВЩИКА (вся логика — в сценариях)
- Прогон как набор сценариев; успех прогона — успех всех сценариев, включая негативные
- Ручной запуск прогона через фронтенд
- Отчёт по прогону

## 4. Архитектура
### Принцип
Ядро ТЕСТИРОВЩИКА работает только с интерфейсами.
Внешняя логика, сущности JSON/SOAP подключаются через адаптеры — реализации этих интерфейсов.
Обновление библиотек адаптеров не должно затрагивать работоспособность ядра ТЕСТИРОВЩИКА
